# 智变链产品需求文档
> 工程变更影响分析智能体 参赛原型

版本 v1.0　编制日期 2026年9月11日　状态 需求基线

本 PRD 将智变链申报方案转化为可开发、可演示、可验收的产品要求，供产品设计、开发、测试及参赛材料制作使用。文中的功能、指标与计划均为建设要求，不代表已实现能力。

## 1 产品目标与关键决策

### 1.1 产品定位
面向中小制造企业工程变更评审，读取新旧图纸及配套业务资料，识别尺寸变化，检查下游文件和业务对象，输出可追溯、可由工程师确认的影响清单。首个场景为电子控制器外壳安装孔尺寸变更。

用户完成一次任务后，应能回答：哪里变了、哪些对象需要处理、结论依据在哪里、还有哪些资料不足，以及下一步由哪个部门核查。

### 1.2 首版实施决策
首版采用单人操作的本地浏览器应用，由同一操作者演示工程、质量和物料管理岗位。部门作为处理任务的责任标签，不建设账号权限及跨部门审批系统。默认以明确订单清单作为变更生效范围；日期、批次区间等自动生效规则留到后续版本。

每个变更任务分析一个零件的两个版本，支持多个已匹配尺寸特征。系统能够导入多个 BOM、检验项和库存订单记录，但只沿已提供的关联字段追踪影响。输入不清楚时允许人工修正并留痕。

### 1.3 首版成功标准
在主案例中识别孔径变化、发现旧检验标准未同步、正确列出相关旧版库存及在制品，且不把未纳入生效范围的订单判定为违规。每项事实和规则推导结果都能定位到原始文件；用户能够完成评审并导出与当前分析版本一致的报告。

### 1.4 需求口径
P0 为参赛原型必须完成的需求，P1 为有余量时实现的增强项，P2 为后续产品化方向。FR 编号对应功能要求，BR 编号对应业务规则，AC 编号对应功能验收场景，NFR 编号对应非功能要求。文中的数量、文件限额及运行策略是本版产品决策，不是赛事平台限制。

## 2 用户需求与版本范围

### 2.1 用户与使用时机
典型触发为收到客户工程变更通知，或工程人员发现新旧图纸不一致。系统使用者主要为准备变更评审材料的工程人员，质量、生产及物料管理人员使用同一份分析结果进行核查。

| 岗位 | 核心诉求 | 可观察的完成结果 |
| --- | --- | --- |
| 工程 | 快速确认变更特征及适用版本 | 查看新旧标注，确认差异与匹配关系 |
| 质量 | 防止按旧要求检验新版产品 | 看到不一致检验项及来源，采纳更新建议 |
| 物料管理 | 找到需要处置评审的旧料 | 查看具体批次、版本和数量，不自动报废 |
| 生产 | 确认在制品与订单要求 | 区分需核查对象和明确不在范围的订单 |
| 评审负责人 | 形成可交接的结论 | 完成采纳、修改、驳回或待核查并导出报告 |

### 2.2 功能优先级
P0：任务创建、资料导入、字段映射与修正、新旧尺寸比对、明确订单生效范围、检验标准检查、库存与在制品关联、证据定位、人工评审、部门处理清单、PDF 与 CSV 导出、分析重试和示例模式标识。

P1：材料变化、更多文件版式、影响关系图、批量任务、报告 Word 导出、更丰富的运行统计。P1 功能未完成不影响 P0 验收，也不应出现在视频中作为已实现能力。

P2：ERP 或 MES 接入、多人协同审批、复杂 CAD 几何分析、企业级权限、工艺参数自动优化及生产执行闭环。首版不直接修改源文件、库存或订单。

### 2.3 用户主流程
新建任务后导入新旧图纸和配套资料，检查提取字段并确认变更对象。系统完成差异和影响分析，用户从结果列表进入原文核查，逐项处理建议，最后导出评审报告。任一步发现资料错误，修正后生成新一轮分析，旧结果保留为历史。

只有新旧图纸时，可形成尺寸差异报告，影响范围标为未覆盖；这不等于完成全部业务评审。演示主案例必须提供本 PRD 第 12 节规定的完整资料。

## 3 页面结构与交互要求

### 3.1 页面与主要操作
桌面端优先，按任务组织内容。用稳定导航切换资料、差异、影响和评审，不要求用户通过聊天逐步寻找结果。

| 页面 | 必须显示的信息 | 主要操作与反馈 |
| --- | --- | --- |
| 任务列表 | 任务名称、零件、新旧版本、状态、更新时间、模式 | 新建、搜索、打开；空列表提供新建及示例入口 |
| 任务资料 | 文件角色、版本、解析状态、字段映射、缺失项 | 上传、替换、预览、修正、设置生效订单、开始分析 |
| 变更对比 | 特征标识、新旧值与公差、变化类型、匹配状态 | 按特征筛选，打开左右原文，修正错误匹配 |
| 影响分析 | 对象、结论类型、处理优先级、证据、覆盖情况 | 按部门或对象筛选，查看原因链，进入评审 |
| 评审与导出 | 逐项决定、修改理由、责任部门、任务清单 | 保存评审、完成评审、导出草稿或已评审报告 |

### 3.2 共用证据侧栏
从差异、影响或处理任务点击证据，打开同一证据侧栏。PDF 展示页码并高亮区域；表格展示工作表、原始行号及对应字段；文本展示原文段落。多来源结论允许逐一切换证据。高亮无法定位时至少显示完整页面或整行，明确提示定位精度有限。

证据侧栏须显示文件名、文件版本及属于哪一次分析。原始文件不可在侧栏直接编辑；字段纠错入口返回任务资料，避免修改提取值却仍引用旧分析结果。

### 3.3 页面反馈规则
顶部持续显示任务的新旧版本、当前分析编号和真实分析或示例模式。分析中显示真实阶段及已处理文件数，不展示随机增长的假进度。没有差异时显示“未发现已确认的尺寸变化”；没有导入某类资料时显示“未覆盖”，不能显示“无影响”。

颜色只辅助区分状态，必须同时显示文字。人工改动即时保存并反馈成功或失败；离开存在未保存编辑的表单时提醒。导出按钮明确区分草稿和已评审报告。

## 4 状态流转与分析版本

### 4.1 任务状态
任务状态由当前输入版本和最近一次有效分析派生。每个任务同时只允许一个活动分析；连续点击开始分析必须返回同一个活动记录。

| 状态 | 进入条件 | 可执行操作与退出条件 |
| --- | --- | --- |
| 草稿 | 新建任务或修改了输入 | 编辑资料；必需字段齐全后开始分析 |
| 分析中 | 已创建运行快照并开始处理 | 查看进度或取消；禁止直接编辑本轮输入 |
| 待补充 | 关键字段缺失或匹配冲突 | 补充或修正后创建新分析；可导出不完整草稿 |
| 待评审 | 分析结束且可形成有效差异或无变化结论 | 逐项评审；有未处理结论时仅能导出草稿 |
| 已评审 | 当前轮全部结论已做决定且满足完成条件 | 导出已评审报告；输入变化后回到草稿 |
| 失败 | 当前运行出现无法恢复的错误 | 查看阶段与原因，重试或修改输入 |
| 已取消 | 用户取消当前运行 | 查看已有过程记录，再次启动新运行 |

### 4.2 输入与结果绑定
每次运行保存资料文件哈希、输入修订号、字段修正、生效范围、模型配置、规则版本及开始结束时间。模型输出、差异、影响、人工决定和导出报告均绑定运行编号。

新增、替换或移除文件，修正字段或生效范围时，必须增加输入修订号，将旧结论标为历史，不再允许作为当前结果完成评审。重新分析不沿用旧的采纳或驳回决定；可查看历史决定作为参考。运行中先取消再修改资料。

### 4.3 评审完成条件
已确认差异所需的零件、特征、单位和版本冲突必须解决。每条结论都已采纳、修改、驳回或转为待核查；转待核查的事项必须填写责任部门与待补资料。有后续待核查事项时，允许完成本轮评审，但报告必须标示“存在未决事项”，不能宣称变更已获批准。

没有变化时仍需用户确认无变化结论和检查覆盖范围。取消后到达的迟延响应不得写回当前结果；旧报告内容保持不可变，下载历史报告时明确标示历史版本。

## 5 任务与资料功能需求

### FR01 创建和查看任务 P0
创建字段包括任务名称、零件编号、旧版本、新版本、业务说明和生效订单清单。任务名称为 1 至 80 个字符；料号和版本视为区分大小写的字符串，仅去除首尾空白，不丢弃前导零。新旧版本不得相同。系统生成唯一任务编号，资料和结果持久化后可再次打开。

允许先保存字段不全的草稿。开始差异分析至少需要料号、新旧版本和对应图纸。缺少生效订单时可做差异分析，但订单适用性标记为未覆盖，不能给出整批失效结论。

### FR02 导入与检查文件 P0
支持 PDF、XLSX、UTF-8 CSV、DOCX 和 TXT；DOCX 先支持正文段落和表格，不承诺浮动文本框及批注提取。每任务最多 10 份有效文件，每份不超过 20 MB，合计不超过 100 MB；PDF 合计不超过 30 页，业务表格合计不超过 1,000 条数据记录。超限必须在分析前说明具体原因。

选择文件角色：旧图纸、新图纸、变更通知、BOM、检验标准、工艺说明、库存、在制品或订单。同一图纸版本只允许一份有效文件；替换文件必须明确指出被替换项。同名但内容不同的文件不自动覆盖；同一任务内同角色同哈希内容提示重复并不再次计入分析。

### FR03 映射业务字段 P0
表格导入后展示工作表、表头、样例行及必需字段映射。系统推荐映射，用户确认后才生效。源文件不带字段时可填写任务级默认料号或版本，但须明确适用行并记录为人工补充，不能静默套用。

库存、在制品、订单和检验项采用第 10 节数据契约。数值非法、重复记录编号或未知版本的行进入异常列表。缺失可选资料不阻止其他对象分析，但对应覆盖情况必须显示未覆盖。

### FR04 预览和人工修正 P0
预览原文与提取字段，允许修正数字、单位、版本、特征匹配和业务映射。每次修正记录原值、新值、来源位置、操作者、时间和原因。删除任务中的有效文件采用移出当前输入的方式，已被历史报告引用的文件保留；彻底清理历史数据属于后续功能。

## 6 识别与差异比对功能需求

### FR05 提取工程字段 P0
优先直接解析文字和表格；图纸可将页面交给多模态模型提取明确标注。原型必须真实调用模型完成至少一种清晰 PDF 图纸的尺寸提取，不得仅返回主案例预设值。提取字段包含零件、版本、特征、尺寸种类、名义值、上下公差、单位及证据位置。

识别失败或多个候选不能确定时输出待确认，不填入猜测值。扫描图纸仅支持标注清晰且经过测试的版式；其他版式允许人工补充。人工修正后的结果应与原始模型提取结果分别保存，评测不能把人工修正效果算入原始识别准确率。

### FR06 匹配特征与单位归一 P0
先按料号和版本对齐资料，再按特征标识与尺寸种类匹配，必要时用语义生成候选，由用户确认。旧特征一对多或新特征多对一时，不自动选择。未匹配特征列为待核查，首版不自动判定为新增或删除几何结构。

首版支持 mm、cm、m 和 inch，归一为 mm；1 inch 等于 25.4 mm。保留原始表示与标准化值，数值使用十进制定点运算，避免二进制浮点误差触发伪变更。缺少单位时禁止猜测。角度、形位公差、配合代号和复合标注进入不支持项列表。

### FR07 比较尺寸与公差 P0
名义值、下偏差和上偏差独立比较。对称公差展开为一正一负偏差，非对称公差按符号保留。缺失公差不能当作零公差；公差未知时可以确认名义值变化，但不得断言全部要求一致。

对每个匹配特征输出原文、标准化新旧值、变化类型、绝对差值和证据。4.0 ± 0.1 mm 改为 4.5 ± 0.1 mm，应显示名义值增加 0.5 mm、公差不变；0.4 cm 与 4.0 mm 在公差也等价时应显示无实质变化。

没有已确认变化且仍有未匹配或未识别项时，结果应为“已检查项未发现变化，仍有待核查项”。只有全部纳入范围的特征已核查，才能输出本范围内未发现变化。

## 7 影响分析与业务规则

### FR08 检验文件一致性分析 P0
按料号、特征标识和适用版本定位检验项，对比目标版本尺寸与检验要求。明确引用旧要求的项目输出“检验要求不一致”，引用新版图纸和旧检验项两份证据。默认建议质量部门更新评审，不直接改写或发布检验文件。

### FR09 业务对象关联 P0
以 BOM 父子关系定位使用该零件的产品，再关联订单明确需求行；库存和在制品按零件及版本查询。界面区分“明确要求冲突”“相关且需核查”“本次生效范围外”“资料不足”。所有关联结论需展示路径，不能因名称相似就认定被影响。

### FR10 生效范围与影响限制 P0
变更通知的生效订单由模型提取候选、用户确认清单。仅精确匹配订单编号；不把订单编号按大小推断先后。若任务输入与通知不一致，提示冲突，由用户选择并写明依据。日期或自然语言区间不能自动转换成订单集合。

| 规则 | 条件 | 必须产生的结果 |
| --- | --- | --- |
| BR01 | 目标版本图纸与适用检验项尺寸不同 | 检验冲突，列出双向证据并建议更新评审 |
| BR02 | 存在同料号旧版库存 | 进入用途核查清单；不自动认定报废或违约 |
| BR03 | 旧版在制品分配给明确要求新版的订单 | 输出要求冲突；未分配时仅待核查用途 |
| BR04 | 订单明确不在本次生效范围 | 作为范围外对象展示，不计入冲突数量 |
| BR05 | 缺版本、分配关系或生效范围 | 标记受限的分析项，不推断未知关系 |
| BR06 | 孔径变化但缺乏工艺和装配依据 | 建议工程核查，禁止直接确定换模或调参 |

每类数量单独计算。以记录编号去重，不按相同料号合并原始记录；同编号内容冲突时中止该类汇总并提示纠正。库存与在制品不相加为损失，多个订单引用同一批次也不能重复累计批次数量。

## 8 证据与人工评审功能需求

### FR11 证据和结论类型 P0
结论分为事实、规则推导和待核查。事实引用直接原文；规则推导引用前提证据、关联对象和规则编号；待核查说明触发原因、已有依据及缺少的资料。无效引用、跨任务引用或内容不支持结论时，不得以事实或规则推导进入可采纳列表。

证据链接使用系统生成的文档与位置标识，模型不得自行生成文件路径。对模型返回的引用先校验存在性和归属，再检查关键数值与前提。人工可将引用不支持结论的项标记为证据问题，返回修正或驳回流程。

处理优先级与结论类型分开保存。P0 使用“优先处理”和“常规核查”两档：明确检验要求或订单要求冲突为优先处理，旧库存用途及一般工艺疑问为常规核查。不显示未经校准的置信概率。

### FR12 逐项人工评审 P0
结论默认未处理。用户选择采纳、修改、驳回或待核查。采纳保留原文；修改需要填写新结论和原因；驳回填写理由；待核查填写责任部门与所需资料。系统同时保留 AI 原始建议及人工版本，不覆盖来源记录。

人工修改涉及尺寸、料号、版本或生效范围时，必须回到输入纠错并重新分析，不能只改结论文本绕过计算。其他人工补充明确标为人工意见；若无来源，不得变成系统已验证事实。

### FR13 部门处理清单 P0
采纳或修改后的可执行建议、转待核查的事项生成处理条目，包含来源结论、动作描述、责任部门、优先级、未决状态和可选计划日期。驳回项不生成条目，但仍出现在评审记录中。

修改评审决定时更新同一关联条目，不能重复新增；多个结论形成一个条目时保存全部来源结论编号。P0 只管理建议及交接清单，不模拟邮件发送、部门接收、生产执行或真正的流程审批。完成评审表示意见整理完成，不代表相关动作已执行。

## 9 报告与运行管理功能需求

### FR14 报告导出与历史 P0
提供 PDF 评审报告及 CSV 处理清单。报告包含任务与运行编号、新旧版本、分析模式、输入资料清单及哈希、差异、影响对象、数量口径、证据、覆盖限制、人工决定、未决事项、责任部门和生成时间。PDF 内保留可读的页码或行号与原文片段，不能只提供依赖本机地址的链接。

分析未完成或评审未完成时允许导出带明显标记的草稿，不能导出已评审版。已评审报告绑定当次结果快照，后续修改不得改变旧报告；导出清单使用 UTF-8 编码并处理引号、逗号和换行。表格单元格中可能被解释为公式的文本应按文本安全导出。

### FR15 重试与取消 P0
分别展示解析、提取、比对、关联和生成报告阶段。模型单次调用超时为 120 秒；对超时、限流或服务端临时错误最多自动重试一次。鉴权失败和输入格式错误不自动重试，应提示修复方式。每轮分析总时限为 10 分钟，达到时限保留阶段记录并标记失败，不把部分结果伪装为完整报告。

用户取消后 2 秒内反馈已取消并阻止后续写回，即使远端请求无法立即终止。重试创建新运行编号；只有文件哈希、提取配置及解析版本完全相同时可复用已验证的解析产物。测试记录需说明缓存命中，不能将缓存耗时当作首次分析耗时。

### FR16 真实分析与示例模式 P0
真实分析模式必须由当前文件执行解析、模型调用与规则计算。模型配置缺失时明确提示，允许用户主动进入示例模式，禁止静默回退。示例模式仅用于离线讲解，预置内容持续标记为示例，并在报告中同样标识。

示例模式不允许上传任意资料后继续展示预置结论，需提示切换到真实分析。更换真实输入后必须产生新的输入哈希和运行，不能复用硬编码主案例答案。所有准确率和模型耗时评测排除预置示例结果。

## 10 输入数据契约

### 10.1 数据表示与关联约定
编号、料号和版本按字符串保存；数量与尺寸按十进制值保存，不允许负库存或非法数字。业务时间保留时区，界面默认北京时间。每条导入记录保存原文件、工作表或段落、原始行号和来源值，列名映射不改变原始证据位置。

| 数据对象 | 必需字段 | 约束和分析用途 |
| --- | --- | --- |
| 变更任务 | task_id、名称、part_no、old_rev、new_rev | task_id 系统生成；新旧版本不同 |
| 图纸文件 | doc_id、角色、哈希、文件名、版本、页数 | 图纸需关联明确料号；新旧图纸角色不可混用 |
| 工程特征 | feature_id、尺寸种类、名义值、单位、版本、证据 | 上下偏差可为空；为空表示未知，不是零 |
| BOM 行 | record_id、产品编号及版本、子料号及版本、用量 | 多层关系检测循环；缺失版本的路径标为受限 |
| 检验项 | item_id、零件、特征、单位、目标值、适用版本、证据 | 公差分别保存；版本不明时仅列候选，不直接断言冲突 |
| 库存批次 | record_id、批次、零件、版本、数量 | 数量非负；仓位与订单分配为可选字段 |
| 在制品 | record_id、工单、零件、版本、数量 | 分配订单可为空；与库存使用独立记录类型 |
| 订单行 | record_id、order_id、需求零件或产品、要求版本、数量 | 产品需求经 BOM 展开；缺失路径不能强行关联 |
| 生效范围 | 已确认订单编号清单、来源证据或人工依据 | 空清单与未设置分别表示；不按编号推断区间 |

### 10.2 文件提取边界
变更通知和工艺说明作为带段落位置的证据文档导入，提取涉及的零件、版本及订单候选。无法可靠提取的生效条件由用户手动确认并记录依据。空白记录可跳过；包含有效数据但不符合数据契约的记录必须在错误清单中逐条展示。

同一对象在不同文件出现冲突时，同时保存来源并要求用户选择有效记录。跨任务不自动共享人工映射；首版通过相同导入模板减少重复配置，避免把上一任务的默认规则误用于新零件。

### 11.1 结果记录
以下对象是前后端共同的数据契约。字段名可在实现时统一映射，但含义、必填条件及版本绑定不得遗漏。所有列表记录均使用稳定编号，不依赖页面显示序号作为引用键。

### 11.2 服务操作要求
创建任务、导入文件、保存字段修正、开始运行、读取进度、取消运行、读取结果、保存评审及导出报告采用独立操作。写操作传入输入修订号或评审修订号；服务端发现版本过期时拒绝并提示刷新，避免旧页面覆盖新结果。

开始运行和生成报告支持幂等请求标识，重复点击不创建重复运行或重复处理条目。错误响应包含错误代码、用户可读原因、影响对象和可重试标记。查询结果必须按任务与运行编号隔离，不能把不同分析轮次混在同一页面。

### 11.3 建议实现结构
沿用浏览器界面、Python 服务、本地文件存储及轻量数据库方案，文件解析、模型适配、规则计算、证据定位、评审与导出分别封装。框架和模型供应商不作为产品验收条件；启动说明必须记录实际版本和所需配置。

## 12 主案例数据与功能验收

### 12.1 可复现主案例
全部数据标为模拟。零件 HSG-001 的 H1 由 A 版直径 4.0 ± 0.1 mm 改为 B 版 4.5 ± 0.1 mm。模拟通知 ECN-001 只明确要求 SO-NEW-001 使用 B 版；旧版订单 SO-OLD-001 继续按 A 版执行。

QI-001 为现行通用检验标准，H1 仍写 4.0 ± 0.1 mm，拟用于新版订单，因此应被标为要求不一致。设置 A 版库存 600 件且未分配订单，B 版库存 100 件；A 版在制品 200 件且未分配订单。三类记录分别编号。BOM 关联目标产品，另放入不同料号库存作为干扰。

| 验收编号 | 操作或输入 | 必须观察到的结果 |
| --- | --- | --- |
| AC01 | 导入完整主案例并真实分析 | H1 增加 0.5 mm，公差不变；定位到新旧图纸。覆盖 FR01 至 FR07 |
| AC02 | 打开 QI-001 影响项 | 检验冲突；双份证据齐全；建议质量更新评审。覆盖 FR08、FR11 |
| AC03 | 查看库存与在制品 | 600 件库存及 200 件在制品分列待核查；B 版及无关料号不误报。覆盖 FR09、BR02、BR05 |
| AC04 | 查看订单适用范围 | 新订单要求 B，旧订单显示范围外；不声称未知分配已违规。覆盖 FR10、BR04 |
| AC05 | 采纳检验建议并将旧料转待核查 | 生成相应部门条目；填写责任与缺少资料后可完成本轮评审。覆盖 FR12、FR13 |
| AC06 | 导出 PDF 和 CSV | 内容与当前运行一致，报告标示未决事项和模拟资料，CSV 中文完整。覆盖 FR14 |

### 12.2 演示通过条件
完整展示导入、识别、证据核查、人工决定和导出。现场调整新版 H1 数值后重跑，结果必须随输入变化；文件名、任务名或示例编号不能成为返回固定答案的触发条件。演示不要求真实接入企业系统，但必须明确数据来源与运行模式。

### 缺陷分级与放行
阻断缺陷包括数据串任务、错误版本报告、无证据的自动确认、错误扩大生效范围、取消后写回或核心流程无法完成。所有阻断缺陷必须关闭。影响证据定位、人工决定保存或报告内容完整性的严重缺陷，也不得带入参赛交付。

每次修改差异规则、关联规则、字段映射或模型提示后，至少回归受影响场景和完整主流程。测试失败保留输入、配置和输出，修复后使用原案例复验，不能通过删除失败样本提高成绩。

## 14 模型评测与运行目标

### 14.1 评测样本和判分
建立 20 组模拟案例，8 组用于开发，12 组锁定为独立验收集。覆盖主案例、单位等价、公差变化、无变化、资料缺失、版本冲突、范围限制和无关对象。答案在运行前标注，模型推理流程不得读取答案文件；验收集运行后若据此修改规则，该集改为回归集，需补充新的独立集。

变更项按零件、特征、变化字段及正确新旧值匹配；影响项按对象类别、记录编号、版本及关系类别匹配。同一对象可能有多类影响，按完整键去重。未知项及待核查项单独统计，不当作已确认命中。

### 14.2 指标目标
以下均为目标，尚未实测。精确率为正确输出数除以全部输出数；召回率为正确输出数除以全部标注数。采用验收集总计数计算，同时报告每组结果。分母为零时标为不适用，另报告无变化样本的误报数，不能把空输出记作 100% 准确。

| 指标 | 目标 | 统计要求 |
| --- | --- | --- |
| 变更识别 | 精确率及召回率均不低于 90% | 分别报告模型原始结果与人工修正后的结果 |
| 影响识别 | 精确率不低于 85%，召回率不低于 90% | 分别列出检验冲突、关联待核查及范围误判 |
| 证据质量 | 有效引用覆盖率 100%，人工支持率不低于 95% | 存在引用不等于支持结论，两项分开判分 |
| 边界处理 | AC07 至 AC16 的必要行为全部通过 | 不用平均分抵消阻断缺陷 |
| 首份报告 | 固定规模下用时中位数不超过 5 分钟 | 每案例至少 3 次，计入重试；失败单列且不得超过总运行的 5% |

计时从资料上传完成且用户触发分析开始，到首份可查看报告生成结束；人工补充等待另记，人工确认总耗时另记。规模采用 10 份以内文件、30 页以内 PDF、1,000 行以内表格；首次与缓存运行分开统计。超时按失败记录，不能只筛选成功耗时。

记录硬件、网络、模型与参数、提示和规则版本、资料哈希、运行次数、调用量及可获得的费用。效益对照包含人工复核与纠错用时；模拟测试结论不得外推为企业实际收益。

## 15 非功能需求与运行边界

### NFR01 可用性与性能
桌面 Chrome 或 Edge 当前稳定版为验收浏览器，最低视口 1366 × 768。长列表支持分页或滚动，关键按钮始终可达。当前参考环境下，普通本地列表与保存操作的 95% 请求在 2 秒内反馈；模型处理显示阶段，不占用浏览器交互线程。首版全局一次运行一个分析任务，额外启动请求提示已有运行，保留任务草稿。

### NFR02 持久化与恢复
任务、文件、提取结果、人工修正和评审记录落盘。浏览器刷新不丢失已保存内容；服务重启后将中断运行标为失败或可重试，不显示为已完成。数据库写入和报告生成须避免半成品被读取；导出失败允许重试，保留原评审状态。

### NFR03 数据使用与配置
默认服务仅监听本机，不按多租户公开服务交付。模型密钥由环境配置提供，不写入源码包、报告、截图或日志。启用外部模型前，在运行说明和设置中说明哪些资料会发送；首期演示使用模拟资料。更换为真实企业文件时，由使用者确认授权与允许使用的模型服务。

上传内容只作为业务数据，不改变系统指令或工具权限。模型工具限定为任务范围内的读取、提取及分析，不能任意访问本机文件或执行文档内命令。文件检查包括扩展名与实际类型、大小、页数和解压限制；不可解析或密码保护文件应明确拒绝。

### NFR04 可追溯与数据保留
记录文件导入、字段修正、运行、取消、人工决定和导出事件，包含时间、任务、运行与对象编号。日志避免写入密钥和完整敏感原文，证据保存在任务资料中。默认保留历史快照用于复现；说明存储目录和备份方式，不暗中清空历史文件。

### NFR05 中文与导出质量
界面、错误信息、表格及报告使用简体中文，专业字段保留必要编号和单位。PDF 中文可搜索且无缺字，分页不裁切表格；CSV 中文、引号、换行和公式样式文本需通过打开检查。无论模式如何，屏幕和报告中的新旧版本、数量与未决状态必须一致。

## 16 排期与交付完成定义

### 16.1 四周实施顺序
排期以实际开发启动日为第 1 天，按约一个月组织，赛事截止日另以平台为准。日期安排不代表已有团队人员承诺；岗位可以由同一人承担。

| 周期 | 工作范围 | 可检查成果 |
| --- | --- | --- |
| 第 1 周 | 数据契约、主案例、任务资料页、文件解析、模型接入 | 可导入、预览和修正；真实提取可运行 |
| 第 2 周 | 特征比对、订单范围、业务规则和证据侧栏 | 主案例可分析，AC01 至 AC04 通过 |
| 第 3 周 | 人工评审、报告快照、重试取消与异常回归 | AC05 至 AC16 通过，数据可保存和恢复 |
| 第 4 周 | 锁定版本评测、修复问题、录像和材料对齐 | 可复现源码包、测试报告、演示视频及更新申报书 |

### 16.2 交付清单
程序源码包含界面、服务、业务规则、模型适配、依赖清单和不含密钥的配置示例。附模拟输入、独立测试数据、预期答案、测试执行说明及结果。答案资料与推理数据分开，明确不参与模型运行。

运行说明写清安装环境、启动、接口配置、真实分析与示例模式、存储路径、已知限制及常见错误。演示视频连续展示核心流程，如剪辑等待过程需标识。申报书、PRD、程序与视频引用同一版本范围，实测指标以最终记录替换目标表述。

### 16.3 完成定义
所有 P0 功能存在可操作入口；主案例与边界验收符合预期；模型及运行指标按第 14 节报告，未达目标项如实披露且不得存在阻断缺陷。重新启动后可打开任务、查看证据和报告；在独立环境中按说明能够重现示例分析。

### 16.4 后续决策与范围变更
具体模型、界面框架和是否接入真实企业资料在实施时确定，不阻碍本 PRD 定义的主流程开发。新增材料变更、多人审批或系统对接必须列为新需求并估算成本，不能替换证据追溯、边界处理等 P0 能力。

调整需求时保留版本记录，注明变更的 FR、BR、AC 或 NFR 编号及对测试和申报材料的影响。当前 v1.0 将首版固定为单零件双版本、尺寸变更、明确订单范围和单人评审。
