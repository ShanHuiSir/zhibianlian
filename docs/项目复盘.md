# 智变链项目复盘

公开归档日期：2026-10-13。应用版本：v1.0.0。

这是东莞百景大赛开放创新赛道的工程变更影响分析原型。仓库用于再次运行、查看当时的产品决策和核对实际交付，不代表比赛评审结果或企业应用成效。

## 从什么问题开始

工程变更通知到来后，工程、质量、生产和物料人员需要同时核查图纸、检验要求、旧料、在制品和订单。难点既在于提取图纸标注，也在于确认哪些业务对象受本次生效范围约束，并把结论交给人核查。

首个案例限定为电子控制器外壳 HSG-001 的安装孔 H1：A 版 4.0 ±0.1 mm 改为 B 版 4.5 ±0.1 mm。ECN 仅对 SO-NEW-001 生效。随附资料全部为模拟输入。

## 关键产品与技术决策

| 决策 | 原因与代价 |
| --- | --- |
| 本机单人浏览器应用 | 可以复现工程评审闭环；没有多人权限、跨部门审批及生产系统集成。 |
| 模型提取，规则计算，人做决定 | 图纸字段由 DeepSeek 提取，尺寸用 Decimal 比较，业务关联由明确字段建立；识别不清或依据不足仍须人工确认。 |
| 精确订单清单决定生效范围 | 避免按订单号大小或自然语言猜测；本版须人工阅读 ECN 并确认清单。 |
| 每条结论显示来源证据 | 支持工程师回到 PDF 页或表格行核查；扫描图或无法自动核验的引文需要人工复核。 |
| 保存输入修订、历史运行及报告快照 | 修改输入须重新分析，旧报告保持不变；增加状态管理和回归测试成本。 |
| 两种显式分析模式 | 真实 API 和本地结构化规则分别标明；配置失败不能偷偷切换成本地结果。 |

## 实际交付与验证

已交付：资料导入、表头映射、人工订单确认、图纸提取、尺寸/公差比对、检验冲突检查、库存与在制品核查、单层 BOM 和订单关联、逐项评审、PDF/CSV 导出及历史记录。

主案例识别 +0.5 mm，旧检验要求不一致，旧版库存 600 件、旧版在制品 200 件分别待核查。两类数量不合并为损失；旧订单明确在生效范围外。将新版 PDF 替换为 5.0 mm 后，新运行识别 +1 mm，原 0.5 mm 报告保持不变。

2026-09-15 的录像与 [真实 API 运行摘要](实际API运行记录.json) 记录两轮真实调用，各两次成功，耗时分别 3.390 秒、3.212 秒。计时不包含人工评审及 PDF 导出，不能推导通用识别准确率、行业效率收益或运行稳定性。

2026-10-13 公开整理时重新执行已有自动化回归：35 项通过，7 条第三方弃用警告。测试使用临时数据和模型替身，不调用收费接口。本次公开整理没有重新调用真实 DeepSeek API。

需求基线仍保留为 [PRD v1.0](product/PRD-v1.0.md)。没有把未实现目标改写成已交付：具体差异请看 [版本范围说明](版本范围说明.md)。

## 回来复盘时的阅读顺序

1. 阅读 README 的运行方法，并用本地规则跑完整模拟案例。
2. 对照 samples/ECN-001.txt、图纸和业务表，查看每个结论引用的来源。
3. 观看 [演示视频](https://github.com/ShanHuiSir/zhibianlian/releases/download/v1.0.0/demo-v1.0.mp4)，对照 [视频解说词](demo/视频解说词.md) 和示例输出。
4. 阅读原 PRD 与版本差异，区分建设目标、已实现功能及已验证行为。
5. 阅读 engine.py、model.py、app.py 及对应测试，理解计算、提取和状态管理的分工。

## 后续最需要验证的事

优先建立多版式、扫描件、编号缺失和含糊订单范围的独立验收集，分别评估原始提取、人工修正、证据支持及最终规则结果。现有 35 项回归不等于这一验收集。

再核查多层 BOM、复杂 CAD、真实业务表与 ERP/MES 对接的成本。进入多人或公网部署前，需要另行设计身份、权限、任务隔离和服务运维；现有原型仅验证本地单人流程。

## 公开归档内容

仓库包含可运行源码、依赖声明、模拟输入、测试、原始 PRD Markdown、视频与解说词、示例报告、实测摘要和 Logo。没有公开 .env、本机数据库、上传目录、虚拟环境、个人申报书或临时制作文件。第三方中文字体及 Logo 字体许可随附。

本仓库的初次公开整理记录最终交付快照；它没有重建开发过程中不存在的 Git 提交历史。字体使用 Git LFS 保存，视频在 Release 中提供完整 MP4，仓库保留可校验还原的二进制分片，方法见 README。这一归档方式用于绕过本次本机大文件上传超时，视频内容没有重新编码或改动。
